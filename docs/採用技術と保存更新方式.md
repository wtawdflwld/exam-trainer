# 採用技術・保存・更新の記録

要件定義書の確定要件に従い、独立した詳細設計工程を設けず実装時に決定した内容です。対象外の機能は追加していません。

## 構成

- フレームワークなしのHTML/CSS/JavaScript ES Modules。動的サーバー・外部API・ログインなし。
- CSV解析は同梱実装。UTF-8 BOM、RFC 4180相当の引用符・カンマ・セル内改行に対応。ヘッダーと必要な型・ID等の取込可否のみ判定。
- MarkdownはDOM構築による限定実装。HTMLを実行しない。対応記法は教材作成ガイドと同一。
- 数式はKaTeX 0.16.22をローカル同梱。CSSが参照する全フォントも本体更新で保存。CDN不要。
- Node.js 20.11以上の標準APIでビルド・ローカル配信。実行時のNode.jsやnpm依存はなし。
- 試作ZIPは3画面・旧CSV列・別保存形式・対象外機能を含むため新規実装。アイコンのみ再利用。試作教材は同梱せず、元ZIPと旧DBは保持。

## IndexedDB v1

DB名：`personal-exam-pwa:<配信ルートのpathname>`。たとえば `/exam-trainer/`。同じルートの末尾 `/` と `index.html` は同一DB。ブラウザーoriginもIndexedDBの分離単位。

`learning` storeの `current` レコード：

```text
revision: 整数。全書込で増加し、多重タブの古い画面からの上書きを拒否
states: [{id, exam, correct:boolean, answeredAt:ISO8601}]
session: null または {id,exam,version,order:[問題ID],position,answers,phase,settings,startedAt}
  answers: [{id,choice:0～4,correct:boolean,at:ISO8601}] の出題順プレフィックス
  choice=0: わからない
  phase=study / result
lastSettings: null または {exam,times:[JSON化した年度・回ペア],topics:[JSON化した分野・細分野ペア],target,order}
```

未回答は `states` にレコードがない状態。累積解答回数、過去の正解率履歴、お気に入りは保存しません。結果表示用に直近演習1件の内訳だけを保持し、新規演習開始で置換します。

`materials` store：資格IDをキーに `{exam,version,meta,questions,csv,images:パス→Blob,savedAt}`。`__catalog` キーだけは手動取得した資格一覧を保持。教材・カタログは学習バックアップに含めません。

解答時には、固定した選択・判定・解説をすぐ画面へ出し、問題別状態と演習状態を同じレコード・同じIndexedDBトランザクションで保存します。成功はtransaction completeで判定。失敗中はメモリー上に同じ解答を保持し、移動・管理画面・本体更新を止めます。再試行では同じ内容を保存します。強制終了前の未保存解答の永続化は保証できません。

次問移動は位置保存成功後に画面遷移。保存失敗なら同じ問題・解説を維持します。複数タブによる競合はトランザクション内でrevisionを照合し、古い側を拒否します。教材操作もrevisionを更新するため、古い教材を表示する別タブが記録を上書きできません。

## 教材更新

ビルドが資格ごとのCSV・参照画像のSHA-256と設定から教材版を生成し、カタログに記録します。手動更新はネットワークからカタログ、CSV、必要画像を取得し、ハッシュ、CSV取込可否、画像デコードを確認して一時的にメモリーに準備します。最後に資格の教材全体をIndexedDBの1トランザクションで置換します。画像の個別更新と版ポインターだけを別々に確定しません。

通信・ハッシュ・容量・保存失敗時は旧レコードを維持。新旧の同名画像を混ぜません。更新中の強制終了では未コミット候補は使いません。削除は教材レコードだけを削除し、`states` は変更しません。画像を含め教材全体を一度に保持するため、非常に大量の画像ではメモリーと新旧分の保存容量が必要です。

中断演習が使う教材の更新・削除を拒否。復元直後の教材不足時だけ、開始時と同一版であれば取得を許可します。版違い・ID不足なら演習を保持して再開を止めます。完了した演習は教材更新・削除を許可し、版違いの結果復習は開始できません。結果の集計は教材本文なしでも閲覧可能。

## バックアップ schema 1

`{format:'personal-exam-pwa',schema:1,createdAt,learning:{states,session,lastSettings}}`。revisionは端末ごとの排他制御情報のため含めません。削除済みIDも含む全状態を保存します。

復元はキー構成、型、値域、ID重複、演習順・位置、解答の連続性、問題別状態との整合性を全部確認してから確認UIを出します。全置換は単一トランザクション。失敗は旧記録を保持。教材には触れません。未知のschemaは拒否。旧試作版の `kakomon-note-backup` は互換性がないため拒否します。

## アプリ更新

ビルドごとに `releases/<内容ハッシュ>/` とアプリ資源一覧を生成します。インデックスの全JS/CSS/フォント参照もその版の相対パスです。Service Workerは安定した配信ディスパッチャーとして動作し、Cache APIの専用コントロールレコードに **利用承認済み版と候補版** を保存します。

新版の全ファイルをハッシュ照合して保存した後だけ候補に設定します。ナビゲーションは常に承認済み版のindex.htmlを返します。「今すぐ更新」の明示操作でのみ承認済み版を切り替え、当該画面を再読み込みします。Workerのinstall/activateや全タブを閉じたことだけでは承認版が切り替わりません。「あとで」は通知を一時的に隠す操作で、次回再通知されます。

旧タブの版別パスは同じ版のキャッシュを参照し、新版と混ざりません。旧本体キャッシュは自動削除しない選択です。教材・学習DBを本体更新処理から削除しません。初回保存が失敗した場合はオフライン保存済みとは表示しません。

現DB schemaは1のみ。旧試作DBは移行対象として自動変更しません。将来DB変更時はversionchangeトランザクションで段階移行し、削除再作成を禁止する方針です。将来版への移行コードを架空に用意して「移行確認済み」とはしていません。

## UI上の決定

- 仮称「過去問演習」。標準OSフォント、縦スクロール、48px程度の操作領域。常設下部ナビゲーションなし。
- 初回の年度・分野は全選択、対象すべて、順序ランダム。全解除は0件で開始不可。
- 年度は西暦整数・新しい順。表示名はメタデータの上書き、なければ西暦年度。
- 試験回は資格別order昇順。番号順は年度降順、試験回order、コード順、問題番号昇順、ID順。
- 親の一部選択はindeterminate。復元した条件から消えた項目は選択対象を広げず0件を許容。
- 解答直後に解説先頭へスクロール。移動後はページ先頭へ。前の問題・スキップはなし。
- 進捗は現在登録問題だけを母数とし、0件は0%かつ未取得／0件を明示。
